# API响应字段修正总结

## 已完成修正

根据实际联调结果，`docs/修正总结.md` 旧版关于响应字段的理解有误。当前代码和文档已统一为平台实际成功判断：

```python
result.get("result") == "success" or result.get("result_val") == 0
```

## 核心修正内容

### 响应字段的正确定义

```python
# API成功响应示例
{
    "result": "success",  # 字符串，success 表示成功
    "result_val": 0,      # 数字，0 表示成功
    # ... 其他业务数据
}
```

### 关键要点

| 字段 | 类型 | 成功值 | 失败值 | 说明 |
|------|------|--------|--------|------|
| `result` | 字符串 | `"success"` | 错误描述文本 | 处理结果说明 |
| `result_val` | 数字 | `0` | `1`, `2`, `3`... | 处理结果码 |

### 正确的判断方式

```python
# 正确
if result.get("result") == "success" or result.get("result_val") == 0:
    print("成功")

# 错误
if result.get("result") == "0":
    print("成功")
```

## 使用示例

```python
from api_client import APIClient, is_success_response, format_api_error

client = APIClient()
success = client.login("admin", "123456")

if success:
    result = client.get_device_overview()
    if is_success_response(result):
        print("获取成功:", result.get("result"))
    else:
        print(f"获取失败 {format_api_error(result)}")
```

## 注意事项

1. 成功判断应优先复用 `api_client.is_success_response()`。
2. `result_val` 是错误码字段，成功时为数字 `0`。
3. `result` 是结果说明字段，成功时为字符串 `"success"`。
4. 不要再使用 `result == "0"` 作为成功判断。
5. `OpenWnd` 成功只表示平台接受开窗命令；仍需用 `GetDisplayWallWnds`
   验证窗口是否真实存在于目标输出区域。如果日志已有 `开窗确认` 但物理屏无画面，
   应继续检查编码器输入信号、设备在线状态、解码器 HDMI 输出和显示器输入源。
6. Web 页面预览是独立的 WebSocket 取流链路。如果平台返回的编码器 MAC
   已包含 `00-01` 通道号，取流通道应为 `MAC/v3`，不能再重复追加
   `-00-01/v3`。
7. 物理大屏窗口存在且输入状态正常时，Web 预览仍可能因为 8003 未回帧、
   浏览器不支持 H.265 或 H.264 AnnexB 解码兼容性导致黑屏，应结合页面状态
   和 `video_stream` 日志继续定位。
